# 夕飯自動化

楽天レシピから月・火・水・金の夕飯を選び、3人分の材料・買い物リストをスマホで確認できます。

## ページを更新する

**`夕飯を更新.bat` をダブルクリックしてください。**

農水省の価格確認、献立の選択、元レシピの分量取得、3人分への換算、HTML作成、GitHub Pagesへの公開まで実行します。
完了すると公開ページが開きます。スマホでもページを再読み込みしてください。

https://okh-degital.github.io/dinner-menu/

対象は日本時間で次に来る月曜日の週です（月曜当日を含みます）。
同じ週の献立が記録済みでも、対象週の履歴を判定から外して再抽選し、その週の履歴を置き換えます。何度押しても履歴は二重登録されません。
丼物は週0〜1回、タコライスは暦月0〜1回。サラダは主菜にせず、対象週の直前4週間の同じレシピID・判定可能な同じ料理を避けます。
有効な農水省データで割安な主材料があれば加点します。古い価格や取得に失敗した区分は加点しません。

曖昧な分量は推測せず別の候補を探します。それでも4日分そろわなければ、現在のHTMLと履歴を残して停止します。
詳しい使い方・止まった場合の対応は `ONE_CLICK.md` を参照してください。

個別に実行するときは次のコマンドです。

```powershell
.\.venv\Scripts\python.exe update_dinner.py --publish --open
```

`main.py` を引数なしで実行する旧動作は、固定の仮献立を生成します。通常の更新には上のbatを使ってください。

## GitHub Pagesの初回設定

1. GitHubに用意したリポジトリへ、このプロジェクトを `main` ブランチとして登録します。
2. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にします。
3. **Actions → Publish dinner page → Run workflow** を実行します。
4. 完了後、**Settings → Pages** に表示されるURLをスマホで開きます。

以後は `夕飯を更新.bat` で `output/index.html` と献立履歴をGitHubの `main` に反映すると、公開ページも更新されます。
公開処理が配信するのは `output/` の中身です。
公開リポジトリを使う場合は、ソースコードなどリポジトリ内のファイルも閲覧できます。

## 表示と買い物チェック

月・火・水・金の「この料理だけ変更」を押すと、その曜日だけを再抽選し、4日分の買い物リストを集計し直します。何度でも押せますが、その曜日に最初に表示された料理と現在表示中の4品は候補から外れます。条件を満たす候補が尽きた場合は、その旨を表示します。保存済みの分量がない候補は、材料名と「不明」を表示します。

変更後も食材名・必要量・不明分の内訳が同じチェックは引き継ぎます。変更とチェックは同じ端末・ブラウザで再読み込みすると復元されます。ブラウザが保存を制限している場合は、開いている間だけ有効です。新しい週や新しい献立に更新すると、そのページの初期献立から始まります。ブラウザでの変更はPCの週次生成履歴には書き込みません。

### PCからスマホへ献立を共有する

「献立をスマホに共有」に表示されるQRコードを読み取るか、「共有URLをコピー」でリンクを渡してください。QRコードは1品変更するたびに更新されます。共有URLを開くと、その時点の4品と買い物リストが表示され、チェックは各端末で管理できます。スマホでさらに変更した場合は、その画面から新しいQRコードを共有できます。

共有URLは常にGitHub Pagesを指します。公開済みページと同じ献立データの版で利用してください。週の更新などで版が変わったリンクは復元できない旨を表示し、通常の献立を開きます。

## 検索への掲載

HTMLに `noindex, nofollow` を設定しています。これは検索エンジンへの指示であり、閲覧を制限するものではありません。

参考: https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages

## デスクトップから更新

「夕飯を更新」を起動すると4品まとめて生成し、Chromeで表示します。
同じ週の再生成では直前4品の楽天カテゴリを除外します。4品そろわない場合だけ、過去4週間の料理も再利用します。
前回の料理そのものと同じカテゴリは復活させません。魚介重複・丼物等の上限は維持し、それでも不足する場合は元のHTMLと履歴を保持します。
別の週の初回生成は従来どおり直前4週間を除外します。正常に生成できた場合はGitHub Pagesにも公開します。

同じ週のやり直しでは、一度表示した料理のID・判定できる料理ファミリーを`data/weekly_plan.json`に累積保存し、2回前以降の献立にも戻りません。
過去の週の料理を再利用する場合も、このやり直し履歴は除外します。対象週が変われば累積除外は引き継ぎません。
通常起動では追加の楽天カテゴリを毎回選び直し、前回未取得のカテゴリを優先します。
候補が尽きた場合は同じ献立を復活させず、現在のHTML・履歴を保持して候補不足を表示します。
